## LOW findings (non-blocking)

1. **LOW — sveltekit `tsconfig.json` extends `./.svelte-kit/tsconfig.json`**
   The file does not exist until `npm run sync` (or `svelte-kit sync`) has run.
   A fresh clone + `npm install` alone leaves `npm run check` / `tsc --noEmit`
   unable to resolve the extends. This is documented in the README
   ("Prerequisites: Node 20+") but the prerequisite is implicit.
   Mitigation: `npm run check` already runs `svelte-kit sync` first in its
   script, so the documented command works. Cosmetic only.

2. **LOW — `templates/nextjs-convex/convex/tasks.ts` imports `./_generated/server`**
   which is produced by `npx convex dev` / codegen and is gitignored. The
   template as shipped will not typecheck until the user runs Convex codegen.
   This is explicitly documented in the README and in
   `scripts/verify-templates.sh` (typecheck is out of scope for smoke).
   Consistent with the template's "starter" intent — not a defect.

3. **LOW — `templates/sveltekit/package.json` `check` script runs
   `svelte-kit sync && svelte-check`** but `svelte-kit` binary must be on PATH
   (comes from `@sveltejs/kit`). On a fresh install this works because
   `@sveltejs/kit` is a direct devDependency. No issue; noted for completeness.
